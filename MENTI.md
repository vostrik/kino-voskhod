# MENTI.md — подсказки по макету «Восход»

Этот сайт — учебный макет кинотеатра. В нём спрятаны типовые проблемы
производительности и доступности, которые встречаются на реальных сайтах.
Задача — найти их и суметь объяснить.

Ориентир для полноты поиска: **8 проблем производительности** и
**12 проблем доступности**. Автоматика находит только часть — остальное
ищется руками, и это самое ценное в поиске.

## Как открыть сайт

- Онлайн: https://vostrik.github.io/kino-voskhod/
- Локально: `python3 -m http.server` в папке проекта → http://localhost:8000

## Инструменты

1. **Lighthouse** — DevTools → вкладка Lighthouse → Performance +
   Accessibility, Mobile, throttling по умолчанию. Начни с него,
   но не заканчивай им.
2. **Клавиатура** — положи мышь. Tab, Shift+Tab, Enter, Esc. Всё, что
   делается мышью, должно быть доступно с клавиатуры.
3. **Скринридер** — NVDA (Windows, бесплатно) или VoiceOver (macOS, Cmd+F5).
4. **Контраст** — пипетка DevTools +
   https://webaim.org/resources/contrastchecker/
5. **Performance panel** — DevTools → Performance: запись загрузки,
   скролла, переключения дня. Смотри long tasks и layout shifts.

## Территории поиска

### Производительность

- Картинки: какого размера они запрашиваются — и какого показываются?
  Что грузится, но не видно на первом экране?
- Что блокирует первую отрисовку? Посмотри порядок подключения скриптов
  и стилей.
- Шрифты: как подключены, что происходит с текстом, пока шрифт не пришёл?
- Резервы макета: что может прыгнуть при догрузке?
- JavaScript: что пересчитывается при каждом рендере и на каждое событие
  scroll/resize? Запиши это в Performance panel.

### Доступность

- Язык страницы; alt-тексты — не только «есть ли», но и «полезны ли»;
  иерархия заголовков.
- Всё, на что можно кликнуть: это действительно `<button>` или `<a>`?
  Доберётся ли туда Tab?
- Контраст текста; видимость фокуса; подписи к полям формы.
- Модальное окно: Esc, ловушка фокуса, объявление для скринридера.
- Информация, переданная только цветом.

## Формат отчёта

Для каждой найденной проблемы — три строки:

1. Что нашёл и где.
2. Почему это плохо для пользователя — одной фразой.
3. Какая правка в коде это исправит.

Главный вопрос программы: «Что именно измеряет эта цифра, почему она
плохая и какое изменение в коде реально улучшит пользовательский опыт?»

## Настройка opencode с бесплатной моделью GLM (Windows)

1. **Node.js LTS** — в PowerShell:

   ```
   winget install OpenJS.NodeJS.LTS
   ```

   (или скачать установщик с nodejs.org). Перезапустить терминал.

2. **opencode** — в PowerShell:

   ```
   npm install -g opencode-ai
   opencode --version
   ```

   Если npm недоступен, а scoop есть: `scoop install opencode`.

3. **Аккаунт z.ai** — зарегистрироваться на https://z.ai (доступен из
   России без VPN) и подключить **GLM Coding Plan**, тариф **Lite — $0**.

4. **Подключение модели** — в папке проекта запустить `opencode`, затем:

   ```
   /connect
   ```

   Выбрать **Z.AI Coding Plan** — откроется браузер для входа
   (или вставить API-ключ со страницы
   https://z.ai/manage-apikey/apikey-list).

5. **Выбор модели** — `/models` → `zai-coding-plan / glm-5.3`.

6. **Проверка** — написать: «Что ты видишь в этом проекте?» — агент
   должен ответить и перечислить файлы.

Как работаем с правками: сначала **Tab** (режим Plan) — агент предлагает
план изменений, обсуждаем; ещё раз **Tab** (режим Build) — вносим правки.
Откатиться можно командой `/undo`.
